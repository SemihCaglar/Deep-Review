# Milestone 1 Assumptions

## Scope assumptions
- Milestone 1 covers backend authentication and account-management foundations.
- The implemented Milestone 1 scope includes issues #4, #5, #6, #7, and #8.
- Frontend integration is outside the scope of this milestone implementation.

## Role and account assumptions
- New signups are created as `LabMember` accounts.
- User approval state is stored on the user entity with three possible values:
  - `Pending`
  - `Approved`
  - `Rejected`
- Only approved users are allowed to log in.
- Pending and rejected users are not allowed to log in.

## Authorization assumptions
- Signup approval and rejection endpoints exist and function correctly.
- Coordinator/admin-only enforcement is not fully implemented through dedicated auth middleware yet.
- The current implementation focuses on backend flow correctness rather than a complete authorization infrastructure.

## Security assumptions
- Passwords are stored as hashes, not plain text.
- Password verification is handled through reusable security helpers.
- Failed login attempts are tracked.
- After repeated failed login attempts, the account is temporarily locked.
- Lockout is enforced during login.
- Password reset tokens are stored as hashes, not as raw tokens.
- Password reset tokens expire after a limited time.
- Password reset tokens are single-use.

## Forgot/reset password assumptions
- The forgot-password endpoint always returns a generic success response.
- The system does not reveal whether a given email exists.
- No real email provider integration has been added yet.
- Reset tokens are logged to the backend console for testing purposes.

## Persistence assumptions
- The project currently uses SQLite with TypeORM.
- Schema synchronization is being used for development-time database updates.
- Existing local database state may affect repeated test results unless the database is reset.

## Testing assumptions
- Backend behavior was verified manually using curl-based endpoint testing.
- Manual verification covered:
  - health check
  - signup
  - duplicate email rejection
  - approval flow
  - login success
  - pending-user login rejection
  - logout
  - lockout behavior
  - forgot-password generic response
  - password reset success
  - token reuse rejection
  - old password invalidation
  - new password login success
